## Переменная

Имена переменных (идентификаторы) в JavaScript **не хранятся как строки в памяти** во время выполнения кода. Когда код компилируется или интерпретируется, имена переменных преобразуются компилятором в адреса памяти, по которым хранятся значения переменных. То есть имя — это удобный человекочитаемый ярлык, с помощью которого движок языка находит соответствующую ячейку памяти, где хранится значение. Это похоже на то, как в机器ном коде имена заменяются адресами памяти или регистрами процессора.[2][3]

### Как организовано хранение переменной let count = 1 в памяти

- Переменная `count` при объявлении через `let` создается в области видимости (scope), например, в контексте функции или блока.
- В движке JavaScript для переменных существуют специальные структуры, называемые **контекстами выполнения** или **лексическими окружениями (lexical environments)**. В них хранится отображение из имени переменной (идентификатора) в физическое место в памяти, где находится значение.
- Для примитивных типов, как число `1`, значение хранится **прямо в памяти** (например, в стеке вызовов).
- Значения объектов или массивов помещаются в область памяти под названием **куча (heap)**, а переменная содержит ссылку на этот объект в куче.[1][8][2]

### Наглядная организация

Можно представить так:

```
Лексическое окружение:
  count  --> [ячейка памяти с числом 1]
```

Тут `count` — идентификатор, сопоставленный с адресом памяти, где хранится значение `1`.

Внутри движка это устроено через таблицы символов, которые отображают имена в адреса, а затем данные хранятся в соответствующих местах оперативной памяти.

Таким образом, имя переменной — это метка на уровне кода, а в памяти хранится непосредственно её значение, с которым работает процессор при выполнении.

## CORS

Ошибка, которую вы видите, связана с политикой CORS (Cross-Origin Resource Sharing), которая блокирует запросы к ресурсам из других источников, если они не поддерживают необходимые протоколы. В вашем случае, сообщение "'from origin 'null' has been blocked by CORS policy" указывает, что браузер блокирует запрос, потому что источник запроса имеет origin "null".

Это часто происходит, если вы открываете локальный файл напрямую через файловую систему (например, файл с расширением .html, открытый через file://), а не через сервер (http:// или https://). Браузеры не разрешают кросс-доменные запросы с таких источников из соображений безопасности.


## es-module
ES-модули (ECMAScript Modules) — это стандартная система модулей в JavaScript, введённая в ECMAScript 2015 (ES6). Они позволяют организовать код в отдельные файлы (модули), которые можно импортировать и экспортировать, обеспечивая модульность, изоляцию и повторное использование кода. ES-модули являются частью языка JavaScript и поддерживаются как в браузерах, так и в Node.js (с некоторыми особенностями в настройке).

### Что такое ES-модули?
ES-модули позволяют разделять код на независимые единицы (модули), где каждый модуль:
- Имеет собственную область видимости (переменные, объявленные в модуле, не попадают в глобальную область).
- Может экспортировать функции, объекты, переменные и т.д. с помощью ключевого слова `export`.
- Может импортировать функциональность из других модулей с помощью ключевого слова `import`.
- Автоматически работает в **строгом режиме** (`"use strict"`), что предотвращает определённые ошибки, такие как использование необъявленных переменных.

### Основные характеристики ES-модулей
1. **Синтаксис `export` и `import`**:
   - `export` используется для экспорта функций, переменных или объектов из модуля.
   - `import` используется для импорта экспортированных элементов из другого модуля.
   - Пример:
     ```javascript
     // math.js
     export function add(a, b) {
         return a + b;
     }

     // main.js
     import { add } from './math.js';
     console.log(add(2, 3)); // Вывод: 5
     ```

2. **Автоматический строгий режим**:
   - В ES-модулях строгий режим включён по умолчанию, поэтому нет необходимости добавлять `"use strict"`. Это означает, что, например, присваивание необъявленной переменной вызовет `ReferenceError`.

3. **Однократная загрузка**:
   - Модули загружаются и выполняются только один раз, даже если импортируются несколько раз в разных местах.

4. **Асинхронная загрузка в браузере**:
   - В браузере модули загружаются асинхронно, что улучшает производительность.

5. **CORS для загрузки**:
   - В браузере ES-модули подчиняются политике CORS, поэтому их нельзя загружать через протокол `file://`. Требуется сервер (`http://` или `https://`).

### Почему нужен `type="module"` в браузере?
В браузере, чтобы использовать синтаксис `import` и `export`, необходимо явно указать атрибут `type="module"` в теге `<script>`:

```html
<script type="module" src="main.js"></script>
```

- **Причина**: Без `type="module"` браузер интерпретирует JavaScript-файл как обычный скрипт, а не как модуль. В обычных скриптах синтаксис `import`/`export` не поддерживается, что приводит к ошибке `Uncaught SyntaxError: Cannot use import statement outside a module`.
- Атрибут `type="module"` сообщает браузеру:
  - Загружать файл как ES-модуль.
  - Разрешить использование `import` и `export`.
  - Активировать строгий режим.
  - Загружать зависимости (импортируемые модули) асинхронно с учётом CORS.

```javascript

// В ES-модулях строгий режим включён, поэтому необъявленные переменные вызывают ошибку.
export function task1() {

// В ES-модулях строгий режим активен по умолчанию, поэтому "use strict" избыточно.

    "use strict"; // Игнорируется

}

// Задание 4: Использование зарезервированного слова
// В строгом режиме зарезервированные слова нельзя использовать как имена переменных.

// Задание 5: Использование eval в модуле
// Код в eval наследует строгий режим модуля, поэтому необъявленные переменные вызывают ошибку.
export function task5() {
    let code = "z = 15; console.log(z);";
    eval(code); // Ошибка: Uncaught ReferenceError: z is not defined
}

// Исправленные версии

// Задание 1 (исправлено): Объявление переменной
export function task1Fixed() {
    let x = 10;
    console.log(x); // Вывод: 10
}

// Задание 5 (исправлено): Корректное использование eval
export function task5Fixed() {
    let code = "let z = 15; console.log(z);";
    eval(code); // Вывод: 15
}
```
